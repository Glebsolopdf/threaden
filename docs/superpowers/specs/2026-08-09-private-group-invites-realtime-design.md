# Приватные группы: приглашения и real-time — дизайн

## Цель

Исправить клиентский сценарий приватных групп: участники должны получать сообщения и
статусы печати в реальном времени, уведомление о доступной истории должно показываться
один раз после вступления, а вход по приглашению должен проходить через отдельный экран
подтверждения.

## Область изменений

- Web-клиент Angular; серверные маршруты и контракты не меняются без доказательства,
  что текущей клиентской подписки недостаточно.
- `/invite/:inviteToken` отображает экран приглашения, а не чат.
- Экран содержит аватар группы, название, текст `Вас пригласили в группу`, кнопки
  `Принять приглашение` и `Отмена`.
- После принятия приглашения выполняется существующий `POST /v1/invites/{token}/join`,
  затем открывается `/groups/:groupId`.
- В диалоге создания группы добавляется блок для ссылки приглашения. Разрешены:
  чистый токен, относительный путь `/invite/<token>` и абсолютный URL только с
  текущим origin. Внешние origins, `javascript:`, `data:`, `blob:`, пути к файлам и
  прочие схемы отклоняются до любого сетевого запроса.
- После вступления приватной группы плашка истории показывается один раз на 10 секунд.
  Факт показа хранится в `sessionStorage` по идентификатору группы; повторное открытие
  или перезагрузка в рамках сессии плашку не возвращают.
- Real-time сообщения и typing проверяются на клиентском уровне regression-тестами.
  События должны применяться только к текущей группе, а typing — только к участникам
  этой группы; до вступления приватная группа не подписывается на чатовые события.

## Архитектура и поток данных

`GroupComponent` получает `inviteToken` и переключает presentation state: invite view
до вступления, chat view после перехода на `/groups/:groupId`. `GroupsStore` сохраняет
текущую группу и выполняет join, но не знает о разметке приглашения. Парсер ссылки
приглашения будет чистой клиентской функцией без сетевых эффектов; shell передаст
полученный токен в существующий маршрут.

`EventStreamService` продолжает принимать SSE. `GroupsStore` применяет сообщения к
текущей группе, а `TypingStore` — к group id из события. Если тест выявит, что private
member events теряются из-за клиентского состояния, исправляется только этот boundary;
серверная рассылка по `GroupMemberIDs` остаётся источником авторизации.

## Ошибки и безопасность

- Невалидная или внешняя ссылка не вызывает HTTP-запрос; показывается локальная ошибка.
- Ошибка загрузки приглашения и ошибка вступления используют существующий notification
  store с понятным сообщением.
- Кнопка `Отмена` возвращает на главную страницу без изменения членства.
- Токен не логируется и не преобразуется в URL другого origin.

## Проверки

- Unit-тесты для безопасного разбора токена из raw token, relative path, same-origin URL
  и отказа external URL/unsupported scheme.
- Unit-тест для одноразового показа history banner state.
- Regression-тесты для merge message и typing event в private group.
- Существующие Angular tests, production build, backend tests и лимиты файлов/каталогов.
