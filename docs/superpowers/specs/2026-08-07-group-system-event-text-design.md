# Текст системных событий групп

## Цель

Убрать тексты событий членства из backend. Backend сохраняет и публикует
структурированное системное сообщение, а web-клиент выбирает отображаемую
фразу. Визуальный вид и действия текущих системных сообщений сохраняются.

## Контракт

Для новых системных сообщений API и SSE `message_created` возвращают:

```json
{
  "kind": "system",
  "event": "member_joined|member_left|member_removed",
  "body": ""
}
```

Остальные поля сообщения (`id`, `group_id`, `author`, `created_at`, `reply_to`)
остаются без изменений. `author` — участник, к которому относится событие.
Отдельные `member_*` события продолжают использоваться для обновления списка
участников.

Старые записи без `event` остаются совместимыми: клиент показывает их текущий
`body`, а backend не меняет исторические данные.

## Архитектура и тестирование

Backend хранит `event` рядом с `kind` и передаёт его через public view. Angular
добавляет тип события в API-модель и централизованно формирует текст в функции
представления системных сообщений. Компоненты групп продолжают использовать
тот же `MessageView`, поэтому стили, копирование, reply и удаление не меняются.

Тесты проверяют, что backend не генерирует готовую фразу, новый event доходит до
API/SSE, клиент формирует три текущих текста и использует body для legacy-записей.
