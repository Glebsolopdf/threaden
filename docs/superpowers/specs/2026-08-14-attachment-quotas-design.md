# Квоты и удаление вложений — спецификация

## Цель

Добавить в окно аккаунта раздел «Квоты», где пользователь видит действующие ограничения вложений, текущее использование и может запланировать удаление всех своих сообщений с вложениями через 5 минут.

## Пользовательский интерфейс

Пункт «Квоты» располагается сразу после «Профиль» в навигации аккаунта:

`Профиль → Квоты → Настройки → Безопасность → Кастомизация`

Раздел показывает значения, полученные от backend:

- занятое место и лимит хранения пользователя — 50 МБ;
- суточное использование и лимит — 20 МБ;
- входящий размер медиа — 10 МБ;
- максимальный размер обработанного фото/видео — 1 МБ;
- максимальный размер архива — 5 МБ;
- максимум вложений в одном сообщении — 3;
- автоматическое хранение — 72 часа;
- минимальный резерв свободного места сервера — 5 ГБ.

В опасной зоне раздела находится кнопка «Удалить все вложения». Перед постановкой удаления отображается подтверждение. После подтверждения интерфейс показывает время выполнения и кнопку «Отменить удаление». Повторное открытие аккаунта восстанавливает состояние с сервера.

Удаляются целиком сообщения пользователя, содержащие его вложения, включая текст подписи. Остальные сообщения и вложения других пользователей не затрагиваются.

## Backend API

- `GET /v1/account/quotas` возвращает лимиты, текущее использование и состояние запроса удаления.
- `POST /v1/account/attachments/delete-all` создаёт один отложенный запрос на удаление через 5 минут. Повторный вызов возвращает существующий запрос.
- `DELETE /v1/account/attachments/delete-all` отменяет собственный ожидающий запрос.

Все endpoint защищены текущей сессией. Идентификатор пользователя берётся только из авторизации, не из тела или query-параметров.

## Хранение и выполнение

В базе появляется таблица отложенных запросов удаления с уникальным ожидающим запросом на пользователя, временем создания и временем выполнения. Cleanup-процесс каждую минуту выбирает просроченные запросы ограниченными batch-порциями.

Для каждого пользователя cleanup удаляет сообщения, связанные с его вложениями, физические файлы и метаданные вложений. Операция идемпотентна: повторный запуск не восстанавливает и не удаляет чужие данные. После выполнения запрос удаляется.

## Ошибки и ограничения

- Если запрос уже ожидает выполнения, новый запрос не создаётся.
- Отмена после начала выполнения не допускается и возвращает понятную ошибку.
- Ошибки базы и файловой системы не раскрывают внутренние пути клиенту, но логируются на сервере.
- Публичные значения квот вычисляются из конфигурации backend, чтобы UI не расходился с фактическими лимитами.

## Проверки

- unit-тесты лимитов, постановки и отмены запроса;
- тест выполнения удаления только собственных сообщений и вложений;
- HTTP-тесты авторизации, повторного запроса и отмены;
- frontend-тесты отображения квот и состояний кнопок;
- полный backend test suite, frontend tests, type-check, build и проверка архитектурных лимитов.
