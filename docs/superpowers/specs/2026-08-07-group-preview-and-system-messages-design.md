# Предпросмотр групп и постоянные служебные сообщения

## Цель

Сделать публичные группы пригодными для просмотра до вступления, разрешить
авторизованным пользователям открывать их профиль, сохранить служебные
сообщения о входе/выходе/исключении после обновления страницы и сохранить
приватность истории новых участников частных групп.

## Решение

Служебные события будут храниться в существующей таблице `group_messages`.
Сообщение получает тип `chat` или `system`; автором system-сообщения является
пользователь, вызвавший событие, а `body` содержит отображаемый текст.
Системные сообщения используют существующий контракт сообщений, поэтому их
можно удалять владельцу, копировать и цитировать в ответах без отдельного
журнала и отдельной пагинации.

### Правила доступа

- `GET /v1/groups/{id}` остаётся публичным для публичных групп и закрытым для
  незнакомых пользователей приватных групп.
- `GET /v1/groups/{id}/messages` отдаёт ограниченный preview последних
  сообщений публичной группы даже неучастнику.
- История приватной группы доступна только участнику.
- Для приватной группы история участника фильтруется по его `joined_at`, так
  что сообщения до вступления не показываются.
- Профиль публичной группы доступен только аутентифицированному пользователю,
  но без членства; профиль приватной группы требует членства.

### События

При успешном входе, выходе или исключении создаётся постоянное system-сообщение
и отправляется SSE-событие с тем же сообщением. Сообщение входит в общий
лимит/срок хранения истории, удаляется владельцем тем же endpoint, что и обычное
сообщение, и может быть целью `reply_to_id`.

### Web-интерфейс

Клиент получает `kind` сообщения из API. System-сообщения отображаются отдельной
стилизацией, но используют общие действия reply/copy/delete. Для публичного
неучастника показывается плашка «Это предпросмотр» с объяснением правил и
кнопкой вступления. Для приватного нового участника отображается плашка о том,
что история до вступления скрыта. Skeleton загрузки группы заменяется на
мягкую поэтапную анимацию с аватаром, заголовком и строками preview.

## Изменяемые границы

- `model`, schema migration и `store/groupmessages`: тип сообщения, запись и
  чтение с фильтром по моменту вступления.
- `groups` service и HTTP handlers: публичный preview, профиль без членства для
  public, генерация постоянных system-сообщений.
- Angular API models/store/components/styles: новый тип, действия сообщений,
  preview/history плашки и загрузочная анимация.
- Интеграционные и компонентные тесты покрывают доступ, фильтрацию,
  постоянство, действия и визуальные состояния.

## Ошибки и совместимость

Старые записи считаются `chat`, поэтому миграция не меняет их смысл. Поля
`kind` и `system` добавляются обратно совместимо: старый клиент продолжит
видеть текст сообщения, новый клиент применит специальный вид. Приватные
данные не должны попадать в публичный preview ни через group summary, ни через
messages endpoint.

## Проверки

Нужно выполнить Go unit/integration tests, Angular tests, development build,
`gofmt`, `go vet`, проверку file/directory limits и ручную проверку маршрутов
через запущенные backend/web сервисы. Перед завершением backend и web должны
быть перезапущены через `threadenctl`.
